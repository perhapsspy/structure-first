# Decisions

**2026-08-28**

- activation 성능은 이번 실험에서 검증하지 않았으므로 frontmatter description과 invocation policy를 유지한다.
- 핵심 본문은 owner 선택, 최소 완료 조건, 필요한 흐름, 구조 요구, total effect, non-competing path, stable-owner verification을 직접 소유한다.
- 공개 I/O·ownership·async·representation·migration과 boundary evidence의 세부 조건은 main에서 의무적으로 route하는 한 단계 reference로 이동한다.
- Ponytail의 default-on trigger, mode, output limit은 포함하지 않으며 publish, Project Legibility sync, release는 A/B 결과 검토 뒤 별도 결정으로 남긴다.

**2026-08-28**

- 새 owner/completion 사례 24 cells는 세 arm 모두 계약을 만족해 후보의 의미 회귀가 관찰되지 않았다.
- 기존 판별 root-cause 12 cells는 current full 2/4, candidate main 4/4, candidate routed 3/4로 핵심 본문의 salience 개선을 재현했다.
- reference 강제 주입은 후보 main보다 낫지 않았으므로 routing 조건을 넓히지 않고 실제 경계 변경에만 읽게 한다.
- token·시간은 cache와 실행 편차가 커 성능 채택 근거에서 제외하며, 후보는 correctness와 의미 보존 기준으로 검토한다.

**2026-08-28**

- 사용자가 한글 문구를 포함한 progressive-disclosure 후보의 canonical 반영을 승인했다.
- 정본 commit과 공개 `main` push 뒤 그 full SHA로 Project Legibility source pin과 생성 bundle을 동기화한다.
- description과 invocation policy는 유지하므로 제품 역할·선택 계약은 바꾸지 않는다.
- plugin version, CHANGELOG, tag, GitHub Release와 publisher pin은 별도 release 작업에 남긴다.
