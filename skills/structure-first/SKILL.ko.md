# Structure First

> 영문 기본 문서: `SKILL.md`
> 설명 동기화: 변경이 여러 단계의 흐름, 상태 생명주기, 부작용·판단 소유권, 단위 간 조합이나 경계 계약을 새로 만들거나 재편하는 코드 생성, 기능 작업, 버그 수정, 리팩터링과 코드 리뷰에 씁니다. 기존 구조 때문에 이런 요소를 추적하거나 검증하기 어려운 경우에도 씁니다. 구조 변경은 선택 사항입니다. 기계적 수정, 일회성 실험과 일관된 국소 변경은 현재 책임 단위와 집중된 검증으로 처리합니다.

## 목적과 경계

요청된 동작을 코드에 자연스러운 형식으로 읽고, 바꾸고, 검증할 수 있게 한다. 구조적 단순성, 재사용, 추상화보다 추적 가능한 동작과 소유권을 우선한다. 구조 변경은 선택 사항이며 그대로 둠, 인라인화, 합침, 삭제, 순서 변경, 추출은 모두 정상적인 결과다.

기계적 수정, 일회성 실험, 일관된 국소 변경은 현재 owner에 둔다. 사용자에게 보이는 버그는 구조를 바꾸기 전에 관찰 가능한 실패와 이를 책임지는 현재 단위를 확인한다.

미확정 제품 목적은 purpose-fit design, representation 사이 의미 소유권은 semantic boundary design, 순수 async interaction·freshness는 interactive-state flow에 둔다. 해당 workflow가 있으면 사용한다. 독립 설치라면 빠진 선행 계약을 밝히고 명시적 사용자 권한 안에서만 해결한다. 확정 계약을 다시 열지 않으며 미확정 계약의 구현 메커니즘을 여기서 만들지 않는다.

## 구조 계약

증상이나 출력 위치가 아니라 동작이나 규칙을 소유하는 가장 작은 **현재 단위**를 고른다. 의도와 관찰 가능한 최소 완료 조건을 밝히고 명령형 흐름, 상태 전이, 이벤트 생명주기, 규칙 집합, 데이터 흐름, 프로토콜 경계처럼 자연스러운 읽기 형식으로 추적한다. 그대로 두면 요청 동작, 계약, 의미 있는 검증이 깨지는 caller, type, test, doc, config만 포함한다.

변경이 만들거나 재편하는 구조 요구—흐름, 생명주기, 부작용·완료 소유권, 조합, 경계 계약—와 추적·검증을 막는 기존 마찰을 확인한다. 현재 단위가 변경과 집중된 검증을 이미 맡고 있으면 그 안에 머문다.

국소 명확화와 구조 변경이 둘 다 신뢰할 만할 때만 비교한다. **Primary Flow**는 명령형 조정의 top-down으로 읽히는 주 경로이며, branch와 exception이 핵심 인과 흐름을 가리지 않게 한다. **Atom**은 관련 없는 책임과 조율하지 않고 동작을 바꿀 수 있는 독립적으로 이해 가능한 역할이다. 어느 쪽도 추출을 의무화하지 않는다.

전체 효과로 선택한다. 복잡도를 없애거나 독립 책임 안에 유용하게 가둘 때만 구조를 바꾼다. helper chain, wrapper, context object, config, state, error channel, lifecycle을 포함한 전체 경로를 확인한다. 상위 코드가 짧아져도 복잡도가 이동했을 뿐이면 개선이 아니다.

조합은 자연스러운 owner에서 찾을 수 있게 하고, 서로 다른 판단과 생명주기는 각 owner에 둔다. 부작용 소유권과 실패 의미를 드러내며, 별도 경계가 추론, 검증, 재시도, 교체를 실질적으로 개선할 때만 부작용을 격리한다.

미확정 선택에 사용자 권한이 필요하거나 공개 API, 데이터, 보안, 의존성·비용, migration에 되돌리기 어려운 약속을 만들면 결정을 요청한다. 그 밖에는 되돌릴 수 있는 국소 가정을 사용하고 알린다.

## 소유권과 Migration

- 공개 I/O와 signature는 확정된 최소 책임으로 시작한다. 실제 새 외부 입력, 의미 혼합, 경계 이동이 있을 때만 키우고 미래 사용을 위한 option, config, dependency, abstraction을 추가하지 않는다.
- policy, decision, calculation, priority, key-generation rule마다 경쟁하지 않는 결정 경로 하나를 둔다. 단일 owner, 명시적 조합 순서, 조정·충돌 규약일 수 있다.
- 외부에서 관찰되는 write owner를 찾을 수 있게 한다. 여러 writer는 조정 자체가 명시적 책임이고 찾을 수 있는 owner나 protocol이 있을 때만 허용한다. 의도된 writer를 자동으로 중앙화하지 않는다.
- async 경계의 freshness와 completion 결정 경로를 owner 또는 protocol로 명시한다. 소유권·reset 의미 없이 상위 경계 상태를 local mutable state로 복제하거나 같은 input/update 경로에 자기 되먹임을 만들지 않는다.
- 이번 변경으로 쓰이지 않게 된 코드를 제거한다. rule owner가 이동하거나 같은 외부 결과를 내는 새 경로가 생기면 같은 변경에서 구경로를 제거·비활성화하고, 어렵다면 staged migration owner와 종료 조건을 둔다.

## 검증

가장 안정적인 책임 단위에서 충분한 관찰 계약—입출력, 불변조건, 경계값, 소유 경계 동작—을 검증하고 helper 내부 구현은 고정하지 않는다. orchestration이나 integration이 위험을 소유하면 현재 단위를 직접 테스트한다.

위험과 변경 종류에 맞춘다. 버그는 수정 전에 재현하거나 현재 동작을 규명하고, refactor는 전후 안정 동작을 지키며, feature는 성공·실패·관련 경계를 검증한다. 여러 가능한 원인을 바꾸기 전에 실패를 좁힌다.

async·stateful 경계에서는 stale result, balanced completion, equivalent-input no-op를 해당 계약 owner에서 검증한다. 테스트는 읽기 쉽고 한 핵심 주장에 집중한다. 검사를 실행할 수 없으면 이유와 다음 유용한 검사를 밝힌다. 테스트를 추가할 수 없으면 이유, 다음 안정 책임 단위, 필요한 계약 사례를 밝힌다.

현재 단위, 구조 요구, 선택한 결과, 판단 소유권·migration 상태, 검증은 task에 도움이 될 때만 보고한다. 계획이나 단순 국소 작업에 템플릿을 강제하지 않는다.
