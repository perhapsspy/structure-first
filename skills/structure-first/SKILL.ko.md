# Structure First

> 영문 정본: `SKILL.md`
> 적용 범위: 여러 단계로 이어지는 흐름, 상태의 수명주기, 판단·부작용의 책임, 단위 간 조합, 경계 계약을 새로 만들거나 다시 구성하는 코드 생성, 기능 개발, 버그 수정, 리팩터링, 코드 리뷰에 사용합니다. 기존 구조 때문에 이런 요소를 추적하거나 검증하기 어려울 때도 사용합니다. 구조 변경은 필수가 아닙니다. 기계적인 수정, 일회성 실험, 한 책임 단위 안에서 끝나는 변경은 현재 구조를 유지하고 필요한 부분만 검증합니다.

## 목적과 경계

동작을 책임지는 곳을 찾고 완료 지점까지 흐름을 따라간다. 실제 책임이 있는 가장 작은 단위만 바꾸고, 외부에서 확인할 수 있는 계약으로 결과를 검증한다.

## 실행 계약

1. 문제가 드러난 위치가 아니라 동작이나 규칙을 실제로 책임지는 가장 작은 **현재 단위**를 고른다. 변경 의도와 외부에서 확인할 수 있는 최소 완료 조건을 밝힌다. 버그라면 구조를 바꾸기 전에 먼저 실패를 재현하거나 확인한다.
2. 호출부에서 출발해 판단이나 상태, 쓰기나 부작용을 거쳐 완료에 이르는 데 필요한 경로만 추적한다. 코드가 본래 읽히는 방식을 따르고, 그대로 두면 동작·계약·검증이 깨지는 타입, 테스트, 문서, 설정만 범위에 포함한다.
3. 이번 변경이 새로 만들거나 바꾸는 구조적 요구가 무엇인지 밝힌다. 흐름, 수명주기, 판단·부작용·완료의 책임, 조합 관계, 전환 절차, 경계 계약 가운데 무엇이 달라지는지와 현재 추적·검증을 가로막는 요소를 확인한다.
4. 먼저 현재 책임 단위 안에서 흐름을 분명하게 만든다. 전체 복잡도가 실제로 줄거나 독립적으로 바꿀 책임을 분리할 수 있을 때만 구조를 바꾼다. 보조 함수, 래퍼, 문맥 객체, 상태, 오류 처리, 수명주기 뒤로 복잡도를 옮기고 상위 코드만 짧게 만드는 것은 개선이 아니다.
5. 각 판단, 쓰기, 부작용, 완료 조건을 최종적으로 결정하는 경로는 하나로 분명하게 드러나야 한다. 같은 결과를 내는 옛 실행 경로는 이번 변경에서 제거한다. 당장 제거할 수 없다면 전환 작업을 책임질 주체와 종료 조건을 밝힌다.
6. 보조 함수의 내부 구현이 아니라 가장 안정적인 책임 단위에서 관찰 가능한 동작을 검증한다. 다른 단위가 계약 일부를 책임진다는 증거가 나오면 그와 관련된 가장 작은 단위만 추가로 살핀다.

현 구조 유지, 인라인화, 합치기, 삭제, 순서 변경, 추출은 모두 가능한 결과다. 나중에 쓸지도 모른다는 이유로 옵션, 설정, 의존성, 래퍼, 추상화를 추가하지 않는다.

## 필수 세부 규칙

공개 입출력, 판단·쓰기·부작용·완료의 책임, 비동기 작업이나 상태의 수명주기, 표현 형식의 의미, 전환 경로를 바꾸려면 먼저 [구조 경계](references/structural-boundaries.ko.md)를 읽는다.

식별 정보, 정본 데이터, 서로 다른 표현 형식, 외부 시스템 쓰기, 실행 시점·비동기 경계에 걸친 중요한 주장을 입증해야 하거나 버그·리팩터링·기능 작업에 경계 수준의 증거가 필요하면 [검증](references/verification.ko.md)을 읽는다.

현재 책임 단위, 구조적 요구, 선택한 결과, 책임 주체와 전환 진행 상태, 검증 결과는 작업에 실제로 도움이 될 때만 보고한다. 계획이나 단순한 국소 변경에 정해진 보고 형식을 강요하지 않는다.
